# 绘图规则

## 共同视觉规则

- 白底、深色文字和细线，配合固定的低饱和度色卡。边框建议 1–1.5 单位，主要节点用直角矩形；用例椭圆、判断菱形等保留各自语义。
- 模板以 1120 单位宽为起点，正文约 18、注释约 14、标题约 26；根据展示尺寸调整。外边距约 40。
- 使用系统 sans-serif 回退；中文和长名称留出余量，不依赖某个字体的精确字宽。用 text/tspan 手工分行并增大容器。
- 主流程沿一个方向，无障碍时优先用水平、垂直或斜向直线直接连接。往返关系使用两条靠近的反向直线；需要避障时再绕行，不为横平竖直而增加折弯。关联关系不需要方向时不用箭头。
- 箭头在节点边缘结束；连线标签避开交点，不穿过正文。不可避免的交叉必须明确是否连接。
- 标题交代主题；图要回答的问题、范围和详细规则放相邻正文。成图不添加“回答……”副标题、底部说明或配色与线型图例。
- 颜色、分组和线条风格是设计时考虑的视觉组织手段，不向读者解释如何画图。必要的业务含义直接标在节点或对应连线上，如分支条件、基数和 «include»。
- 每张 SVG 自带 xmlns、viewBox、白底、样式、marker、title、desc 和 aria-labelledby。同页内联多图时给 ID 加唯一前缀。
- 按 XML 规则转义 &、<、> 等字符。不使用外部字体、图像、CSS、脚本或 foreignObject。

## 配色与视觉层次

先减少不必要的交叉，再用颜色、线型和明暗帮助追踪关系。背景容器退后，业务节点和关系突出；颜色不能补救错误布局。下列色卡供设计时使用，不作为图内图例展示。

| 用途 | 描边 / 文字 | 浅色背景 |
|---|---|---|
| 可用性：可行 | `#327354` | `#EDF5EF` |
| 可用性：不可行 | `#AA4E4E` | `#FAEEEE` |
| 可用性：不确定 | `#926D20` | `#FBF5E5` |
| 分组 A：蓝 | `#426B91` | `#EEF3F8` |
| 分组 B：紫 | `#786783` | `#F3EFF6` |
| 分组 C：青 | `#477C80` | `#EDF5F4` |
| 分组 D：棕 | `#8A735C` | `#F6F1EB` |
| 背景分区 | `#CBD5DF` | `#F5F7FA` |

正文使用 `#25313A`。分组色不表达好坏，按当前图的对象分配并保持一致。状态判断可使用绿、红、黄，但必须同时有明确的业务文字，不把黄色自动当成失败。

两个维度同时存在时，用容器淡色表达归属、带文字的状态标记表达状态，避免一个颜色同时承担两个含义。失去颜色后仍应能凭节点名称、关系标记和结构理解图意。

## 分组标识与关系布局

### 分组标识应有独立、稳定的阅读位置

将标题放在能够清楚标识分组、又不干扰内容和连线的位置，并预留专属空间。多个同级分组保持一致的标识方式。横向分层可以在侧边设置标题区；其他布局根据分组方向选择位置，不让标题挤在内容或连线经过的区域。侧边标题不是所有图型的固定要求。

- [反例：标题挤在内容与连线之间](examples/group-label-bad.svg)。小字放在容器上沿，与进入分组的连线路径冲突，读者难以分辨标题和内容。
- [正例：独立标题区](examples/group-label-good.svg)。相同内容与连线保留，标题移到预留的侧栏，具有稳定的位置和清楚的字号。

### 节点位置应体现关系的亲疏与共享

布局前先识别直接关联、共同依赖与专属关系。关系紧密的节点适当靠近，共享节点尽量靠近关联节点的视觉中心，专属节点靠近各自的关联对象。通过节点位置减少绕行、交叉和追线距离，不只按照数量平均排列。

当关系本身具有对称性时，可以用对称布局帮助读者识别；关系不对称时应如实表达，不为视觉整齐强行对称。主要阅读方向、业务顺序和分组边界仍需保持清楚。节点尺寸或标签不同，也不必强求相同线长。

- [反例：平均排布忽略共享关系](examples/dependency-affinity-bad.svg)。两个上层接口共享身份与权限，却把共享节点放在一侧，产生较长的斜线和交叉。
- [正例：共享依赖居中](examples/dependency-affinity-good.svg)。相同节点和依赖关系下，共享能力居中，专属能力分居两侧；对称的依赖自然形成对称连线。

先根据关系安排节点与分组，再画连接线；不要先铺等距方框，最后通过绕线弥补布局问题。这些原则同样适用于模块关系、数据关系、系统上下文与泳道，不能改变图本身的语义约束（例如时序图的时间顺序）。

### 同级元素采用一致的布局节奏

对于承担相同结构角色的元素，如同级分组、连续泳道、并列节点和重复卡片，应统一相应的间距、内边距与对齐方式。调整其中一处后，应检查同类元素，避免局部优化破坏整体一致性。

间距可以因关系疏密、内容长度或标注空间而变化，但这种变化应服务于明确的表达需要。例如，用更大间距区分不同业务阶段。没有表达理由时，默认保持一致。

关系决定元素放在哪里，一致性约束同类结构如何排列。共享依赖可以居中、专属依赖可以靠近各自接口；同级分组之间的留白仍应统一，除非需要表达额外含义。

完整应用见[组件架构图](../assets/components.svg)。

## 图型语义

### 系统上下文图

把待分析系统作为一个整体；只画人和外部系统，不混入数据库、控制器等内部实现。标明交互含义，双向关系可用两根错开的箭头。

参考：[context.svg](../assets/context.svg)。

### 用例图

参与者在系统边界外，用例在边界内。关联线不加流程箭头；仅在确实需要时使用 include/extend，并解释语义。

参考：[use-case.svg](../assets/use-case.svg)。

### 业务流程图

主流程保持一个方向，判断用菱形并标明每条分支的条件。回路从外侧绕行；多角色交接复杂时增加泳道，泳道代表责任人。

参考：[flow.svg](../assets/flow.svg)。

### 状态图

节点表示稳定状态，箭头标事件或条件。明确描述哪个对象，避免把生成、支付等不同生命周期塞进同一个状态机。

参考：[state.svg](../assets/state.svg)。

#### 短重试回环：用近邻反向连线表达

当失败处理只是返回相邻步骤重试，且本图不需要展开独立的失败状态时，正向与返回方向使用两条靠近的直线，把“失败重试”写在返回线上。必要的条件（例如用户主动发起）也标在线上，不因简化图形暗示系统自动重试。

反例：[多余失败节点形成尖锐三角回环](examples/state-retry-bad.svg)。图中把“校验失败”“请求失败”单独画成下方矩形，再用斜线和竖线返回，使两个本来很短的重试关系形成尖锐三角形，增加节点和追线负担。

正例：[简化后的状态图](../assets/state.svg)。失败重试直接标在相邻状态间的返回线上，避免为短回环额外添加矩形。

此规则针对当前图的表达粒度；若失败本身需要持久保存、等待处理或承载多个后续分支，应保留独立失败状态，再优化布局。不能为了减少矩形而删掉必要的业务状态。

### 关键时序图

参与者横向、时间向下。区分响应与异步事件；业务时序用领域角色，接口时序用真实组件。分支使用明确标注的区域，不把异步结算画成响应前置条件。

参考：[sequence.svg](../assets/sequence.svg)。

### 数据关系图

明确概念对象图还是物理表图。关系两端标基数，可用 1、0..1、0..N；不能从外键存在推断必有子记录。只列与关系有关的字段。

参考：[er.svg](../assets/er.svg)。

### 组件架构图

先标容器边界，再放组件与依赖；每个节点一个职责。新增/现有/待确认用文字或虚线图例区分，不只靠颜色。不要将示例架构当成项目已确认方案。

参考：[components.svg](../assets/components.svg)。

### 页面线框图

用可识别的框、文本和控件表达信息层级。不要用装饰代替业务信息；可加入编号对应文字规则。复杂交互用多个状态画面，不在一张页面中堆所有状态。

参考：[wireframe.svg](../assets/wireframe.svg)。

## 检查与交付

先检查业务对象和关系，再检查标签闭合、ID 引用、画布边界和文本位置。已有浏览器能力时检查原尺寸和缩小后的呈现；不能预览应说明。XML 解析通过不等于布局和语义通过。

交付 SVG 源文件，不引入转换工具。根据目标平台支持情况提供链接或嵌入方式，不承诺未经验证的兼容性。
